# حالت MQTT — برنامهٔ کاملاً استاتیک

در این حالت **هیچ سروری وجود ندارد**. کل بک‌اند داخل مرورگر است
(`static/js/mqtt-backend.js`) و روی MQTT-over-WebSocket به یک بروکر وصل می‌شود.
به همین دلیل صفحه را می‌شود روی **GitHub Pages** گذاشت.

```
مرورگر کاربر A ──┐
                 ├── MQTT over WebSocket ──→ بروکر (EMQX / HiveMQ / Mosquitto)
مرورگر کاربر B ──┘        pub/sub + retained
```

هیچ دیتابیس، دیسک یا آپلودی در کار نیست؛ «ذخیره‌سازی» همان پیام‌های
**retained** بروکر است.

---

## سه نوع پیام

| نوع | کاربرد | مثال |
|---|---|---|
| **retained** | state — آخرین مقدار هر تاپیک، پس کاربر تازه هم فوراً همه‌چیز را می‌گیرد | کاربران، پست‌ها، گروه‌ها، لایک‌ها، استوری‌ها |
| **غیر retained** | رویداد لحظه‌ای — جایگزین Socket.IO | پیام چت، تایپینگ، سیگنال WebRTC، اعلان |
| **retained + Last Will** | حضور — با بسته‌شدن مرورگر، خودِ بروکر آفلاین را منتشر می‌کند | `presence/<uid>` |

«حذف» در MQTT یعنی انتشار **payload خالی** روی همان تاپیک.

## نقشهٔ تاپیک‌ها

پیشوند همهٔ تاپیک‌ها `jvl/<networkKey>/v1` است تا دو گروه روی یک بروکر عمومی
قاطی نشوند (کلید پیش‌فرض: `volexturn4`).

### state (retained)

| تاپیک | محتوا |
|---|---|
| `user/<uid>` | پروفایل کاربر (نام، بیو، آواتار، نقش، هش رمز) |
| `uname/<username>` | نگاشت نام‌کاربری → شناسه (برای ورود) |
| `presence/<uid>` | `{online, at, name}` + Last Will |
| `group/<gid>` | مشخصات گروه |
| `member/<gid>/<uid>` | عضویت و نقش |
| `post/<pid>` | پست (متن + رسانه به‌صورت data URL) |
| `like/<pid>/<uid>` | لایک (بودن تاپیک = لایک شده) |
| `view/<pid>/<uid>` | بازدید یکتا به ازای هر کاربر |
| `cmt/<pid>/<cid>` | کامنت |
| `story/<sid>` | استوری + `expires_at` |
| `sview/<sid>/<uid>` | بینندهٔ استوری |
| `follow/<follower>/<followee>` | دنبال‌کردن |
| `lan/<hid>` | سرور بازی شبکهٔ محلی |
| `pin/<scope>` | پیام سنجاق‌شدهٔ هر گفتگو |

### رویدادها (غیر retained)

| تاپیک | رویدادها |
|---|---|
| `evt/dm/<uid>` | `msg` · `edit` · `delete` · `seen` · `pin` · `typing` · `clear` |
| `evt/group/<gid>` | همان‌ها برای گفتگوی گروهی |
| `evt/notify/<uid>` | اعلان لایک/کامنت/فالو |
| `evt/voice/<room>` | سیگنال WebRTC (offer/answer/ICE) |
| `evt/global` | `post_like` · `post_comment` · `post_view` · `follow_update` · `groups_changed` · `post_deleted` · `message_deleted` |

هر کلاینت یک‌بار `jvl/<key>/v1/#` را subscribe می‌کند؛ هم state از retainedها
ساخته می‌شود و هم رویدادها می‌رسند.

## تشخیص خودکار حالت

`index.html` همیشه لایهٔ MQTT را بارگذاری می‌کند. لایه، اول `api/app_info` را
با `fetch` اصلی صدا می‌زند:

- اگر **سرور نود** پشت همان آدرس بود (پاسخ بدون فیلد `transport`) → همهٔ
  درخواست‌ها به سرور واقعی واگذار می‌شود و `socket.io.min.js` بارگذاری می‌شود.
- اگر نبود (مثلاً روی Pages) → **حالت MQTT** فعال می‌شود.

پس یک `index.html` هم روی Pages کار می‌کند هم روی سرور محلی، بدون تغییر.

مسیر رسانه هم از `mediaURL(kind, value)` رد می‌شود: در حالت MQTT یک
`data:` URL برمی‌گرداند و در حالت REST همان `/files/<kind>/<name>`.

## تنظیم بروکر و کلید شبکه

```js
JVL.setBroker('wss://broker.hivemq.com:8884/mqtt');  // تغییر بروکر
JVL.setNetworkKey('khdodemon');                      // شبکهٔ اختصاصی خودت
JVL.state.ready();                                   // وضعیت اتصال
JVL.mode();                                          // 'mqtt' یا 'rest'
```

یا مستقیم در localStorage: `jvl_broker` و `jvl_network`.

بروکرهای عمومی آماده:

| بروکر | آدرس WebSocket |
|---|---|
| EMQX (پیش‌فرض) | `wss://broker.emqx.io:8084/mqtt` |
| HiveMQ | `wss://broker.hivemq.com:8884/mqtt` |
| Mosquitto | `wss://test.mosquitto.org:8081/mqtt` |

## محدودیت‌های این حالت (مهم)

1. **بدون امنیت واقعی.** روی بروکر عمومی هر کسی می‌تواند تاپیک‌ها را
   subscribe کند. هش رمز هم قابل خواندن است. ورود/ثبت‌نام فقط برای جلوگیری
   از ورود تصادفی است. برای استفادهٔ جدی، بروکر خصوصی با TLS و ACL بگذار.
2. **تاریخچهٔ چت ماندگار نیست.** پیام‌ها غیر retained هستند (وگرنه بروکر عمومی
   زیر بار می‌رفت)، پس هر مرورگر فقط پیام‌های همان نشست را نگه می‌دارد.
   با رفرش، چت خالی می‌شود — ولی کاربران، پست‌ها، استوری‌ها، گروه‌ها، لایک‌ها
   و فالوها (همه retained) سر جایشان می‌مانند.
3. **ویدیو پشتیبانی نمی‌شود** و عکس/صوت به ~۱۹۰KB فشرده می‌شود، چون بستهٔ
   MQTT روی بروکرهای عمومی حدود ۱MB سقف دارد.
4. **«اولین کاربر = مدیر» رقابتی است.** اگر دو نفر هم‌زمان ثبت‌نام کنند ممکن
   است هر دو مدیر شوند. بعداً از پنل مدیریت قابل اصلاح است.
5. **شمار بازدید/لایک با تأخیر همگام می‌شود** (در حد چند صد میلی‌ثانیه).
6. استوری‌های منقضی توسط خودِ کلاینت‌ها فیلتر می‌شوند؛ تا وقتی کسی صفحه را باز
   نکند، تاپیکشان روی بروکر می‌ماند.

## دیپلوی روی GitHub Pages

Pages این مخزن روی شاخهٔ جاری و مسیر `/` تنظیم شده، پس **هر push یعنی دیپلوی**:

```bash
git push origin arena/ac24cb6b-jvl-platform
# چند ثانیه بعد:  https://javadxpro.github.io/JVL.PLATFORM/
```

چون همهٔ مسیرهای `index.html` نسبی هستند، زیردامنهٔ `/JVL.PLATFORM/` مشکلی
ایجاد نمی‌کند (لایهٔ MQTT هم این پیشوند را از مسیرهای API حذف می‌کند).

اگر خواستی روی `main` منتشر شود، منبع Pages را در
`Settings → Pages → Source` به `main / (root)` تغییر بده.
